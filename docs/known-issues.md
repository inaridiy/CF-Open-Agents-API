| Rootless Docker                            | `wrangler dev` (and `pnpm test:containers`) with rootless Docker: the session and the containers start, but every turn fails with `internal_error` or `connection_failed`. The Worker log's `Native harness diagnostics` shows `error sending request for url (http://model.internal/v1/responses)` and `failed to connect to exec-server websocket ws://sandbox.internal/: Connection reset by peer` while ingress (Worker to container) succeeds. Wrangler's proxy-everything sidecar publishes the ingress ports but expects the Docker bridge gateway (`172.17.0.1`) for egress to be in workerd's namespace, which under rootless Docker is rootlesskit's namespace. | Use the `dev:rootless` script that `create-cf-open-agents-api init` offers when it detects a rootless engine (or `init --rootless`): it runs `wrangler dev` inside rootlesskit's network namespace with `nsenter` and bridges the port back to the host, the recipe in [deployment.md](deployment.md#local-runtime-notes) automated. The repository smoke uses that recipe by hand. Rootful Docker and Docker Desktop are unaffected. The script is a temporary workaround for Wrangler's local container proxy assuming a rootful bridge, to be removed when Wrangler supports rootless engines. Not yet reported upstream for rootless engines; the closest report is [workers-sdk#15257](https://github.com/cloudflare/workers-sdk/issues/15257) (the same egress gateway unreachable from Docker Desktop on WSL2). Recheck when Wrangler's container emulation changes how containers route back to the host. |
